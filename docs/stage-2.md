# 第二阶段：本地开发验收与自动回归

验收日期：2026-11-02。本阶段按本地开发、个人测试场景实施，没有部署线上服务。

## 1. 浏览器与工作区

使用真实 Chromium 检查 1440、1024、390、320 像素宽度，覆盖长会话名、长模型名、自动保存、保存失败、手动重试及窗口缩放。布局测试中的模型、PocketBase 和画板 API 使用固定响应；下面数学验收使用真实 GeoGebra。

发现并修复：窄屏下身份信息与模型选择区域互相挤压，同步文字出现后导航高度变化。现在窄屏分行显示，预留同步状态高度，长状态截断并保留完整提示。正常自动保存期间，“重试同步”不会出现；实际保存失败后出现，重试成功后消失。

## 2. PocketBase 与邮件

使用 PocketBase 0.40.4，加载项目实际迁移和钩子，创建独立临时数据库及本地 SMTP 收件服务。测试结束关闭进程并删除临时数据。未修改开发数据库、现有用户或邮件配置。

通过 7 组业务检查（Node 报告含父测试共 8 项）：

- 注册邮件实际发送到本地 SMTP；验证码重复发送限制和一次性使用。
- 连续 5 次输错后，原验证码失效。
- 会话创建、重命名、完整画板 XML 保存、服务重启后读取及跨用户读写隔离。
- 真实身份校验、用量写入和按用户汇总；普通用户不能伪造用量。
- 密码重置后旧密码及旧登录令牌失效，验证码不能重复使用。
- 新邮箱验证、换邮箱及跨用户验证码隔离。
- 删除账号级联删除其会话和用量，其他账号仍可登录。

邮件已验证到本地 SMTP 接收环节；外部邮箱投递、垃圾邮件判定不属于本次本地验收。

## 4. 后端回归与 GitHub Actions

新增鉴权网络异常、用量写入失败、SSE 分块、令牌隔离、缺少 usage、取消请求、上游错误和 JSON 响应计量测试。

修复三个复现问题：PocketBase 鉴权连接失败会中断模型请求；用量写入未检查 HTTP 失败状态；非流式 JSON 响应没有读取 Token 数。现在鉴权/计量异常不会阻断本地模型使用，连接设有超时，写入失败记录简短诊断，JSON 与 SSE 均能读取实际用量。计量失败不自动补记；取消或失败的请求不计入完成请求数。

GitHub Actions 在 PR 和 main 推送时执行安装依赖、单元测试、构建、浏览器布局测试、隔离 PocketBase 联调。CI 不需要模型密钥，也不调用付费模型；数学参考命令的策略检查包含在单元测试中。

## 本地复验

```powershell
npm ci
npx playwright install chromium
npm test
npm run build
npm run test:browser
$env:PB_BINARY='D:\pocketbase\pocketbase.exe'
npm run test:integration
```

真实数学测试默认跳过，需明确选择一种方式：

```powershell
# 真实 GeoGebra + 固定参考命令，不调用模型
$env:LIVE_GEOGEBRA='1'
npm run test:math
Remove-Item Env:LIVE_GEOGEBRA

# 真实 GeoGebra + 本地 .env 中的模型，会消耗模型用量
$env:LIVE_LLM='1'
npm run test:math
Remove-Item Env:LIVE_LLM
```

浏览器测试自动启动 5174 端口的 Vite，测试结束关闭自己启动的服务。`test-results/` 保存本次截图、失败跟踪及数学结果 JSONL，下一次浏览器运行会清理该目录；此目录不上传仓库。日常测试仍使用 `npm run dev` 的 5173 端口及已有 PocketBase。
